v9.2.1 — Indicator + Curve-Shape Trial Plan (BTC)

Test whether classical TA indicators + their curve-shape derivatives improve the v9.2 BTC LightGBM head. ~19-day BTC bench, zero production touches.
📅 2026-05-20 Author: claude-session Hub note: docs/HUB_NOTE_2026-05-20_v9_2_1_indicator_shape_trial_plan.md

1 · The motivating idea

Standard TA indicators like RSI(14) compress a 14-candle window into a single scalar. But the trajectory of that scalar over the prior N candles carries more information: direction, magnitude, curvature, persistence. The bet of this trial is that LightGBM can extract signal from those trajectories that the existing 58-feature set doesn't already cover.

Single metric capturing curve behaviour
For each indicator I, compute one number that encodes its full recent trajectory: 
shape_score(I, N, M, λ) = Σᵢ₌₀^(N-1)  exp(−λ·i) · (I[t−i] − M)
Encodes direction (sign), magnitude (absolute value), recency (recent values weighted heavier via the decay), and persistence (sustained excursions accumulate).

3 · The shape-score, visualised

The shape score sums signed deviations from midpoint M, weighted by recency. Recent values count more (decay exp(−λ·i)). One float per indicator captures direction + magnitude + recency + persistence.

4 · The three feature layers

Layer 1 — Raw indicators

5 features
Five base indicators computed on closed 5m candles. Attached to each training row via the candle that closed BEFORE the row's window opened (no look-ahead). 
rsi_14         # RSI(14) over last 14 closed 5m candles
macd_hist      # MACD histogram (DIF − DEA)
kdj_j          # KDJ J line — overshoot indicator
bb_pct_b       # Bollinger %B — position within band [0..1]
ema_slope      # EMA(12) slope normalized

Layer 2 — Shape score (the "single metric" capturing prior curve)

5 features
One float per indicator. Recency-weighted signed integral relative to midpoint. 
shape_rsi    = Σ exp(−λ·i) · (rsi[t−i] − 50)       # M=50 for RSI
shape_macd   = Σ exp(−λ·i) · (macd_hist[t−i] − 0)
shape_kdj_j  = Σ exp(−λ·i) · (kdj_j[t−i] − 50)
shape_bb     = Σ exp(−λ·i) · (bb_pct_b[t−i] − 0.5)
shape_ema    = Σ exp(−λ·i) · (ema_slope[t−i] − 0)

Lookback N=314 closed candles (≈ 26 hours at 5m). Decay λ tuned so the weight of the oldest candle is ~0.2× the most recent.

Layer 3 — Explicit derivatives + integrals

20 features (4 per indicator × 5)
Same lookback. Decomposes the shape into its 4 most-interpretable components. 
d1[I]       = mean(I[t−i] − I[t−i−1])     over i ∈ [0, N)   # slope
d2[I]       = mean(d1[t−i] − d1[t−i−1])   over i ∈ [0, N)   # curvature
area_pos[I] = Σ max(I[t−i] − M, 0)                           # positive integral
area_neg[I] = Σ max(M − I[t−i], 0)                           # negative integral

L2 is the recency-weighted signed integral (one number for "what's the bias"). L3 separates the unweighted positive/negative integrals + adds velocity (d1) + acceleration (d2). L2 and L3 are complementary — L2 emphasises recency, L3 doesn't.

6 · Training pipeline

ticks_binance BTC — 12.16M rows over 19 days raw trades, the only persistent ground-truth price series for BTC
pandas groupby 5min → OHLCV — aggregate to 5m candles 5,472 candles over 19 days; one row per (asset, candle_close_time)
pandas-ta on candle closes — rsi, macd, kdj, bb, ema 5 base scalars per candle = indicator_table 5,472 × 5
rolling-window apply — compute shape_score, d1, d2, area_pos, area_neg 25 derived features per row = shape_table 5,472 × 25
LEFT JOIN to signal_evaluations BTC 5m — attach by window_ts use the SHAPE values from the candle that closed BEFORE this window — no look-ahead
augmented_training_table — 518k rows × 88 features existing 58 + L1 (5) + L2 (5) + L3 (20)
LightGBM × 6 per-Δ heads + 6 isotonic calibrators mirror v9.2 architecture exactly — only the feature set differs
A/B vs baseline v9.2 on held-out test split verdict on whether to wire forward into production

7 · Look-ahead safety guarantees

Single biggest backtesting risk
TA-feature backtests routinely leak future information. Three guards:
  1. Candle-close time t_close is the earliest moment a candle can be used. Any signal_evaluations row at window_ts uses only candles with t_close ≤ window_ts_open.
  2. The current-window's partial candle is NEVER used in feature computation.
  3. All rolling windows have an explicit "as of" time set to candle close.

Verified by a unit test: assert that feature values for a given training row depend only on data with ts < signal_evaluations.window_ts_open.

8 · A/B comparison protocol

To avoid confounding the indicator effect with a data-window or hyperparameter effect, we train TWO models on the SAME 19-day window with the SAME LightGBM architecture, differing only in feature set:

Baseline v9.2-recompute582026-04-28 → 2026-05-18Isolates "indicator effect" from "different data" effect
Trial v9.2.1-indicator-shape882026-04-28 → 2026-05-18Same data + same architecture + 30 new features

Both use 14d train / 3d dev / 2d test (time-ordered). Compare:

  • Held-out log-loss (calibration check)
  • Held-out WR @ conservative thresholds (p≥0.96 UP, p≤0.04 DOWN)
  • Feature importance ranks for L1, L2, L3 features
  • Reliability diagrams at multiple p-bins

9 · Decision matrix

OutcomeAction
Held-out WR ≥ baseline + 1pp at conservative thresholds AND ≥3 L2/L3 features in top-20 importance Wire forward. Implement TaIndicatorCache in app/, retrain for ETH/XRP after backfill completes.
Held-out WR within ±0.5pp of baseline, L2/L3 features mostly low importance Skip. Indicators redundant with existing features. Move on.
Mixed: some L2/L3 features high importance, others low Prune + retry. Cherry-pick top 6 indicator features, redo trial with 64 features (58 + 6).
Held-out WR ≤ baseline − 1pp Skip + investigate. Adding features hurt. Most likely cause: lookahead leak or alignment bug. Don't ship.
